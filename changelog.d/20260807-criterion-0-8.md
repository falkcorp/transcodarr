### Changed

#### criterion 0.5 → 0.8

Redone by hand because the Dependabot PR that proposed it could no longer be
merged. PR #7 was opened on 2026-06-16, before the workspace split, and edits a
`[dev-dependencies]` block in what was then a single-crate `Cargo.toml`. The
root manifest is now a `[workspace]` file and criterion is declared once in
`[workspace.dependencies]`, so the change had nowhere to land — a test-merge
against `main` reported conflicts. It has been closed with that reasoning rather
than left open to look actionable.

The dependency is genuinely live, which is why the bump was worth carrying
across: `crates/transcodarr-cli` takes it as `criterion = { workspace = true }`
and `benches/transcode_benchmark.rs` is a real `harness = false` bench target.

criterion resolved to 0.8.2. The benchmark needed no source change — it imports
only `BenchmarkId`, `Criterion`, `criterion_group` and `criterion_main`, all of
which survive the intervening majors, and it never used `criterion::black_box`,
which is the import that most commonly breaks on this upgrade (it moved to
`std::hint::black_box`).

Verified with `cargo build --benches -p transcodarr-cli` rather than inferred
from the lockfile resolving: a dependency that resolves is not a dependency that
compiles, and the bench is the only thing in the tree that touches this crate.
`cargo fmt -- --check` and `cargo clippy --all-targets --all-features -D
warnings` are both clean.
