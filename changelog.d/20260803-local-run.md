### Added

#### `admin run` — encode, validate, install, on this machine

Wires the executor, the validator and the commit ritual into a runnable
pipeline, with no dispatcher, agents or gRPC. The agent runs in-process, which
is what makes Phase 3 a risk-retirement exercise rather than a
distributed-systems one: the commit ritual is exercised against real media
before any machinery exists that could hide a bug in it.

The order is the safety argument. Encode into the work area, validate, and only
then commit — a failure in the first two steps leaves the library exactly as it
was, and only the third touches the destination.

Recovery of interrupted installs runs *before* any new work is accepted. An
agent that started encoding while an unresolved intent sat on disk could be
handed the same file again and install over its own half-finished replace.

`--dry-run` prints the exact ffmpeg command without running anything.

#### `policy::encode_plan_for` and `policy::validation_spec_for`

Pure builders turning a decision into an encode and a validation contract. They
carry the production rules: every stream mapped (`-map 0`, because a bare `-c:a
eac3` silently drops all but the default track), bit depth preserved rather than
upconverted, and an audio pass permitted to grow the file — re-encoding TrueHD
or Opus to EAC3 640k legitimately does, and requiring shrinkage would reject
every audio job.

### Fixed

#### Source duration is now measured the same way as output duration

Validation compared the source's **container header** duration against the
output's **last-packet PTS**. A packet's PTS is the presentation time of the
last frame, not the end of the file, so it sits one frame below the header
value — and the comparison invented a shortfall that does not exist.

Measured on a real 5-second remux: header 5.000s, source last-packet PTS 4.900s,
output last-packet PTS 4.900s. Against the header that is a phantom 0.1s
shortfall, and a perfectly good output is rejected; against the source's own PTS
it is exact. The runner now re-measures the source the same way at plan time.

This was found by running the pipeline against real media — every unit test
passed with the bug present, because they supplied both durations by hand.
